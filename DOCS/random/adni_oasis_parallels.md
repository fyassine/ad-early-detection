# OASIS3 converter / non-converter rsfMRI subject lists

## Context

ADNI already has a converter vs. stable-MCI cohort definition, materialised as three CSVs in
`DATA/ADNI/__metadata__/` (`Extended_rsfMRI_MCI_{Converters,NonConverters,Longitudinal}_14May2026.csv`)
and generated by
[build_adni_rsfmri_subject_lists.py](DATA/DELCODE/src/processing/build_adni_rsfmri_subject_lists.py).
OASIS3 has no equivalent — only [build_visit_diagnosis.py](DATA/OASIS3/__metadata__/build_visit_diagnosis.py),
which labels *single visits* HC/MCI/AD from CDR staging but has no notion of longitudinal conversion.

The goal is a matching OASIS3 cohort under the same two labels, so downstream code can consume both
cohorts through one schema:

- `converter` — was MCI at some visit, later diagnosed AD
- `non_converter_stable_mci` — was MCI at some visit, never reached AD

### Answer to "can we use all 19 MCI columns as MCI?"

**Yes — all 19 exist in `OASIS3_UDSd1_diagnoses.csv` with exactly the spellings you listed, and
`any MCI column == 1` is a valid MCI rule.** Two findings refine it:

1. **The columns are not sparse — they're skip-logic-gated, and that's correct.** Only ~5.6% of rows
   have an MCI flag populated because Form D1 only asks them when the parent question says so:
   `NORMCOG==1` → dementia questions skipped (CN, done); `NORMCOG==0` → `DEMENTED` asked (1854/1863);
   `DEMENTED==0` → MCI subtypes asked (468/497); `DEMENTED==1` → MCI subtypes skipped (only 9/1378).
   So D1 yields a complete diagnosis for 7662/8499 rows (90%): 5799 CN, 1378 dementia, 485
   cognitively-impaired-not-demented. The MCI flags are populated exactly where they should be.

2. **The 4 parent flags are sufficient.** `MCIAMEM`, `MCIAPLUS`, `MCINON1`, `MCINON2` fire on 224 rows;
   all 16 together fire on 226. Only 2 rows set a domain sub-flag (`MCIAP*` / `MCIN1*` / `MCIN2*`)
   without a parent. We will still test all 16 (harmless, catches those 2), but the cohort is
   parent-driven. Note `IMPNOMCI==1` (250 rows) means *impaired but not MCI* — *excluded* from MCI.

### The real bug: your AD rule drops half the cohort

`AD = DEMENTED==1 AND PROBAD==1` **silently discards every UDS-v3 visit.** OASIS3 spans two form eras
and they are perfectly complementary (1369 of 1378 demented rows answer exactly one):

| Era | Rows | `PROBAD` non-null | `alzdis` non-null |
|---|---|---|---|
| v1/v2 (`dxmethod` NaN) | 4855 | 1131 | 0 |
| v3 (`dxmethod` set) | 3644 | 0 | 3644 |

UDS v3 replaced `PROBAD` with `alzdis` + `alzdisif`. Using `PROBAD` alone loses 515 AD rows
(AD subjects 427 → 269) and is why the MCI→AD count looked implausibly small.

| AD rule | converters | stable MCI |
|---|---|---|
| `DEMENTED & PROBAD` (as proposed) | 23 | 130 |
| **`DEMENTED & (PROBAD \| (alzdis & alzdisif))`** ← chosen | **73** | **85** |
| `DEMENTED` (any dementia) | 89 | 65 |

Confirmed decisions: era-aware AD rule; ±365 d scan-match window (OASIS3 visits are ~annual; ADNI's
±90 d yields only 33 matched visit-scans vs. 122 at ±365 d); emit all three CSVs.

## Deliverable

New script: **`DATA/OASIS3/__metadata__/build_oasis3_rsfmri_subject_lists.py`**

Lives beside `build_visit_diagnosis.py` (which is where OASIS3 metadata code already lives) and mirrors
the ADNI script's structure. Unlike the ADNI script it uses `Path(__file__).resolve()` for paths — not
a hardcoded `BASE = "/mnt/e/..."` — following `build_visit_diagnosis.py:29-35`.

Outputs, dated `date.today().strftime("%d%b%Y")` → `17Jul2026`, into `DATA/OASIS3/__metadata__/`:

```
Extended_rsfMRI_MCI_Converters_17Jul2026.csv
Extended_rsfMRI_MCI_NonConverters_17Jul2026.csv
Extended_rsfMRI_MCI_Longitudinal_17Jul2026.csv
```

## Schema — identical 14 columns to ADNI

```
subject_id,label,viscode,examdate,diagnosis,has_rsfmri_scan,image_id,fmri_visit,
fmri_date,fmri_description,fmri_group,fmri_tr,fmri_te,date_diff_days
```

| Column | ADNI source | OASIS3 source |
|---|---|---|
| `subject_id` | `PTID` | `OASISID` (`OAS30001`) |
| `label` | derived | derived — same two values |
| `viscode` | `VISCODE` (`bl`, `v01`) | `OASIS_session_label` (`OAS30001_UDSd1_d0000`) |
| `examdate` | `EXAMDATE` date | `days_to_visit` **integer** |
| `diagnosis` | 1/2/3 | 1/2/3 — same codes, from D1 |
| `image_id` | numeric scan id | MR session label (`OAS30001_MR_d0129`) |
| `fmri_visit` | `fmri_visit` | MR session label |
| `fmri_date` | date | days-from-entry **integer** |
| `fmri_description` | `fmri_description` | `SeriesDescription` |
| `fmri_tr` / `fmri_te` | ms | `RepetitionTime`/`EchoTime` **×1000** (see below) |
| `fmri_group` | A/B/C by TR | same thresholds |
| `date_diff_days` | `\|fmri_date − examdate\|` | `\|days_image − days_visit\|` |

**Time-axis caveat, to be stated loudly in the script docstring and the README:** OASIS3 is
de-identified and has **no calendar dates** — only days-from-entry. `examdate` and `fmri_date` therefore
hold *integers*, not dates; `pd.to_datetime` on them produces garbage. `date_diff_days` is the one
column that is directly comparable across the two cohorts. Column *names* are kept identical to ADNI so
downstream readers work; the units differ and must be documented. Flag this at review — if it proves
too sharp an edge, the alternative is renaming to `days_visit`/`days_image` and breaking strict parity.

## Implementation

Inputs — both already present, no downloads:
- `DATA/OASIS3/__metadata__/OASIS3_UDSd1_diagnoses.csv` (8499 rows, 1340 subjects) — diagnoses
- `DATA/OASIS3/__metadata__/OASIS3_MR_json.csv` (30339 scan rows) — scan inventory

### 1. Per-visit diagnosis from UDSd1

Guard clauses first, per [errors.md](.claude/rules/errors.md) — raise `ValueError` if any of the 19 MCI
columns, `NORMCOG`, `DEMENTED`, `PROBAD`, `alzdis`, `alzdisif`, or `days_to_visit` is absent, rather than
silently producing an empty cohort. Parse `days_to_visit` with `pd.to_numeric(errors="coerce")` and drop
NaN.

```python
MCI_COLS = ["MCIAMEM","MCIAPLUS","MCIAPLAN","MCIAPATT","MCIAPEX","MCIAPVIS",
            "MCINON1","MCIN1LAN","MCIN1ATT","MCIN1EX","MCIN1VIS",
            "MCINON2","MCIN2LAN","MCIN2ATT","MCIN2EX","MCIN2VIS"]

is_cn  = d["NORMCOG"] == 1
is_mci = (d[MCI_COLS] == 1).any(axis=1)          # IMPNOMCI==1 deliberately NOT MCI
is_ad  = (d["DEMENTED"] == 1) & (
             (d["PROBAD"] == 1) | ((d["alzdis"] == 1) & (d["alzdisif"] == 1))
         )                                        # era-aware: v1/v2 PROBAD, v3 alzdis+alzdisif
```

Compare against `== 1` explicitly, never truthiness: `DEMENTED` has one stray `2.0` and `IMPNOMCI` two,
which are not "yes". Map to ADNI's `diagnosis` codes 1=CN / 2=MCI / 3=AD; rows that are none of the
three (e.g. non-AD dementia, `IMPNOMCI`) get no code and are dropped from visit output, matching the ADNI
script's `DIAGNOSIS.isin([1,2,3])` filter at line 95.

### 2. Classify subjects

Port `_classify` from
[build_adni_rsfmri_subject_lists.py:105-124](DATA/DELCODE/src/processing/build_adni_rsfmri_subject_lists.py#L105-L124)
verbatim in logic, substituting `days_to_visit` for `EXAMDATE`:

- no MCI visit → drop
- any AD visit with `days > first_mci_days` → `converter`, conversion day = min of those
- no AD visit at all → `non_converter_stable_mci`
- AD only at/before first MCI → drop (prevalent AD, not a converter)

Visit-row selection mirrors ADNI step 5: converters keep visits in
`[first_mci_days, first_conversion_days]` inclusive; non-converters keep MCI visits only.
Expected: **73 converters / 85 stable MCI**.

### 3. Attach rs-fMRI

From `OASIS3_MR_json.csv`, strip whitespace from headers (`build_visit_diagnosis.py:72` does this — the
file also has a genuine `acccession` typo, unused here), then:

- filter `scan category == "bold-rest"` → 5114 scan rows / 2138 sessions / 1198 subjects
- **exclude `SeriesDescription == "rsfmri_ref"`** (205 rows, TR=5.0 s) — a reference/calibration scan,
  not a usable rest run
- parse subject and days from `label` via `parse_subject` / `parse_days`, reusing the regexes in
  [build_visit_diagnosis.py:41-49](DATA/OASIS3/__metadata__/build_visit_diagnosis.py#L41-L49)
- **convert `RepetitionTime` / `EchoTime` from seconds to ms (×1000)** — OASIS3 stores BIDS JSON seconds
  (2.2, 0.027) where ADNI stores ms (3000, 30). Without this every scan misgroups as B.
- `fmri_group` via the same TR thresholds (`<1000` → B, `<2000` → C, else A). Post-conversion OASIS3
  yields A (2200/2500/3000 ms) and B (500/806/816 ms); C is expected to be empty.
- dedupe to one row per `(subject, session)` — most sessions have 2 rest runs (1603 of 2138); the
  session is the unit that matches the on-disk BIDS layout `__bold_and_smri__/sub-X/ses-Y/`
- match each visit to the **closest** session within **±365 days**, else `has_rsfmri_scan=False` with
  the fMRI columns NaN — same `sort_values("date_diff_days").groupby(...).first()` shape as ADNI
  `attach_fmri` (lines 177-221). Do **not** copy the dead `set(zip(...))` at lines 202-203.

Expected: 67 of 73 converters and 73 of 85 non-converters have ≥1 rs-fMRI; 122 matched visit-scans
across 84 subjects.

### 4. Longitudinal CSV — define the criterion explicitly

The ADNI `Longitudinal` CSV **has no generator in the repo** — it was produced ad hoc and is not
reproducible; its 406 subjects are a subset of the 488 union subjects with ≥2 scans, but 82 such
subjects are excluded, so "≥2 scans" is necessary yet demonstrably not the actual rule. We therefore
**define and document** the OASIS3 criterion rather than reverse-engineering it:

> Subjects with **≥2 scan-matched visits** (`has_rsfmri_scan == True`), emitting all their rows from the
> converter/non-converter union.

State this in the docstring and README as an OASIS3-specific choice, not an ADNI reproduction.

### 5. README

Extend [DATA/OASIS3/__metadata__/README.md](DATA/OASIS3/__metadata__/README.md) with a section covering:
the two labels; the MCI-via-D1-skip-logic explanation; the v1/v2-vs-v3 `PROBAD`/`alzdis` trap (the single
most valuable thing to record); the days-not-dates caveat; the ±365 d window; the Longitudinal criterion;
and how this differs from `visit_level_diagnoses.csv` (CDR staging, cross-sectional). The README currently
says CDRTOT is staging and `dx1` is the diagnosis — this new script is D1-based, so note why: D1 gives
explicit MCI subtypes and AD etiology, which `dx1` free-text does not cleanly separate.
